# KSU Marietta Parking Permit Optimizer

A **multi-criteria decision-support system** applied to a real commuter parking problem at Kennesaw State University's Marietta campus. It turns a student's recurring schedule, campus geography, parking restrictions, historical conditions, uncertainty, and personal priorities into a ranked semester permit recommendation and day-specific parking plan.

> **Status:** Presentable MVP / demo. The recommendation engine is deterministic; uncertainty is reported separately through sensitivity analysis. This is an independent student project and is **not an official Kennesaw State University service**.

## What this project demonstrates

This project is intentionally broader than a campus parking lookup tool. It demonstrates how an ambiguous real-world decision can be formalized into a transparent software system:

- translating a messy human decision into a deterministic scoring model;
- combining geographic, behavioral, policy, price, and observational data;
- separating **recommendation logic** from **uncertainty estimation**;
- validating user input and converting recurring schedules into parking sessions;
- using sensitivity analysis to show when user priorities or uncertain inputs change the result;
- producing an explainable ranking instead of a black-box answer;
- regression-testing edge cases such as overlapping classes, long gaps, after-hours access, and close permit races;
- presenting the model through a usable Streamlit interface.

The same architecture could be adapted to other decision-support problems involving recurring behavior, constrained options, imperfect evidence, and competing user priorities.

## Try the full model in about 60 seconds

Once the live Streamlit app is open:

2. The app automatically loads example priorities and semester week 1 so the uncertainty and tradeoff features are easy to see.
3. Click **Recommend my permit**.
4. Review the permit ranking, day-specific parking plan, uncertainty/confidence output, and preference-sensitivity section.

The example is designed so that a reviewer does **not** need to know anything about KSU to see the system's major capabilities.

## What it does

- Accepts a recurring weekly class schedule using 12-hour AM/PM input.
- Rejects overlapping classes and other invalid schedule entries.
- Detects long gaps and asks whether the commuter normally leaves campus.
- Converts the week into parking sessions instead of assuming one arrival per day.
- Ranks all commuter permit options using configurable priorities for **walking, reliability, shade, and price**.
- Recommends a preferred lot and an arrival-by time for each parking session.
- Handles after-5 PM flex-parking behavior.
- Reports the runner-up, score separation, search-risk estimates, and recommendation confidence.
- Reruns the same schedule under schedule-conditioned preference tilts to show how the recommendation changes when one priority matters more.
- Flags cheaper alternatives for students who commute only one or two days per week without changing the underlying ranking.

## Why this project exists

A permit is a semester-long purchase, but parking convenience changes by building, arrival time, week of semester, lot layout, and the student's tolerance for walking or search time. The optimizer turns those tradeoffs into one transparent weekly recommendation rather than treating the nearest lot as automatically best.

## Architecture

```text
Streamlit UI (app.py)
        │
        ▼
Schedule validation + session construction
        │
        ▼
Deterministic permit scoring engine
        │
        ├── walking-distance matrix
        ├── lot / shade attributes
        ├── time + semester search-risk modifiers
        └── permit prices / legal areas
        │
        ▼
Ranking + day/session parking plan
        │
        ├── sensitivity-based confidence
        └── preference tradeoff analysis
```

The recommendation itself is not generated by an LLM. See [docs/METHODOLOGY.md](docs/METHODOLOGY.md) for the scoring model and assumptions.

## Data and modeling

Runtime data lives in [`data/`](data/):

- `walking_distances.csv` — mapped walking durations between modeled parking areas and campus buildings.
- `parking_areas.csv` — lot characteristics, shade, occupancy pressure, searchability, and model confidence.
- `permits.csv` — commuter permit names, colors, and Fall 2026 pricing used by the demo.
- `search_risk_modifiers.csv` — time-of-day, semester-phase, and lot-specific risk modifiers.

The model separates normal historical conditions from unusually severe disruption reports rather than averaging crisis conditions into the everyday baseline.

## Limitations

- Search-risk scores are relative decision-support heuristics, **not probabilities** or live occupancy estimates.
- The app does not currently ingest real-time closures, events, construction, weather, or live parking counts.
- Historical/community reports are useful but observational and unevenly distributed across lots and times.
- Walking routes use modeled lot/building anchors rather than individual parking stalls.
- Permit policies and prices can change; the current demo is calibrated to the included Fall 2026 dataset.
- Residential parking is excluded from commuter recommendations even where a permit may have additional residential privileges.
